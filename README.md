# Чувствительность к инсулину — лабораторная №5

Базовое SPA на React и TypeScript для гостевого просмотра расчётов чувствительности к инсулину.

Карточки загружаются из локальной mock-коллекции. Бэкенд, база данных и MinIO для работы ЛР5 не требуются. Оформление перенесено из предыдущей лабораторной работы.

## Основные страницы

### 1. Плитка — `/services`

На странице расположены фильтр по возрасту и карточки расчётов. Каждая карточка содержит изображение, название, возраст, вес, коэффициент чувствительности к инсулину и количество лайков.

| Элемент | Поведение |
|---|---|
| «Фильтр по возрасту» | Ползунок выбирает возрастную группу |
| «Показать» | Применяет фильтр, обновляет `ageRange` в URL и выполняет mock GET |
| Изображение или название | Открывает выбранный расчёт в ленте |
| Сердце и число | Отображают количество лайков; гостю изменение недоступно |

Возрастные группы:

| `ageRange` | Возраст |
|---|---|
| `0` | 18–39 лет |
| `1` | 40–59 лет |
| `2` | 60–89 лет |
| `3` | 80 лет и старше |

До нажатия «Показать» ползунок изменяет только локальное значение поля. После применения фильтра отображаются подходящие mock-карточки.

Пример: `/services?ageRange=0` показывает расчёты для возраста 18–39 лет.

Без параметра `ageRange` отображается вся коллекция. Фильтр сохраняется в URL при обновлении страницы и переходах между плиткой и лентой. При пустой выдаче отображается сообщение об отсутствии расчётов.

### 2. Лента — `/feed`, `/feed/:id`

Лента показывает один расчёт на экран: фоновое видео, название, описание и правую колонку с возрастом, весом, коэффициентом чувствительности и количеством лайков.

| Элемент | Поведение |
|---|---|
| «Ещё ↓» | Раскрывает полное описание; повторное нажатие сворачивает его |
| Кнопка «→» | Открывает следующий расчёт в текущей отфильтрованной коллекции |
| Сердце и число | Только просмотр количества лайков |
| «Плитка» в navbar | Возвращает к списку расчётов с сохранением фильтра |

При открытии `/feed` выбирается первая карточка текущей коллекции. Адрес `/feed/12` открывает расчёт с ID 12.

Переход к следующей карточке выполняет mock-запрос с параметрами `id` и `next=true`. После последней записи показывается первая. Переход учитывает выбранную возрастную группу.

Если запись не найдена, отображаются сообщение об ошибке и кнопка «К плитке».

### 3. Добавление

В ЛР5 создание расчётов не реализовано. Пункт «Добавление» в нижней панели отключён и не открывает форму.

В следующей лабораторной после авторизации пользователь сможет создать расчёт: указать название и описание, при необходимости выбрать фото и видео, затем нажать «Далее» и заполнить возраст и вес. После публикации запись должна появиться в плитке и ленте.

В ЛР5 отдельного маршрута добавления нет, запросы создания и публикации не выполняются.

### 4. Вход и регистрация — `/register`

Форма сохранена в оформлении предыдущей лабораторной. Её можно открыть напрямую по адресу `/register`.

| Поле или кнопка | Поведение |
|---|---|
| «Имя пользователя» | Обязательное поле, от 3 до 100 символов |
| «Пароль» | Обязательное поле, от 8 до 72 символов |
| «Зарегистрироваться» | Выполняет учебный POST в mock API |
| «Войти» | Показывает сообщение о гостевом режиме ЛР5 |
| «Выйти» | Очищает пароль и сообщает об отсутствии активной сессии |
| «Плитка» | Открывает список расчётов |
| «Лента» | Открывает ленту |
| «Swagger» | Ссылка на документацию предыдущей лабораторной; для её открытия нужен отдельно запущенный бэкенд |

Учебная регистрация возвращает статус `201` и объект с полями `id`, `name`, `source`. Пароль не сохраняется и не возвращается в ответе. Настоящая учётная запись и сессия не создаются.

На время запроса поля и кнопки формы блокируются. Результат отображается под формой.

По условию ЛР5 пункт входа в нижнем меню отключён. Форма регистрации доступна только по прямому адресу.

## Нижний navbar

| Пункт | Доступность |
|---|---|
| Лента | Доступен, `/feed` |
| Добавление | Отключён |
| Плитка | Доступен, `/services` |
| Вход / выход | Отключён |

Активный раздел отмечен белой полоской. Отключённые пункты не выполняют запросов и не открывают формы.

Используются компоненты React-Bootstrap `Navbar` и `Nav.Link`.

## Mock и вкладка Network

Коллекция расчётов находится в `src/modules/mock.ts`.

Путь данных:

**Страница → useServices → fetch → MSW → mock-коллекция → JSON → React.**

| Запрос | Результат |
|---|---|
| `GET /api/services` | Все mock-карточки |
| `GET /api/services?ageRange=0` | Расчёты для возраста 18–39 лет |
| `GET /api/services/feed` | Первая карточка |
| `GET /api/services/feed?id=12` | Карточка с ID 12 |
| `GET /api/services/feed?id=12&next=true` | Следующая карточка |
| `POST /api/users/register` | Учебная регистрация: `201` или ошибка проверки данных `400` |

Параметр `ageRange` передаётся также в запросы ленты, если выбран фильтр.

Обработчики запросов находятся в `src/mocks/handlers.ts`, подключение MSW — в `src/mocks/browser.ts`. Mock API запускается до первого рендера приложения.

Для проверки откройте **DevTools → Network → Fetch/XHR**, затем обновите страницу, примените фильтр или перейдите к следующему расчёту.

В Network видны адрес запроса, статус и JSON-ответ. Заголовок `x-data-source: mock` обозначает источник данных. Запросы перехватывает Service Worker, настоящий бэкенд не вызывается.

В режиме React StrictMode первоначальный GET может отменяться и выполняться повторно. При смене страницы или параметров предыдущий запрос отменяется через `AbortController`.

## Изображение и видео по умолчанию

Локальные файлы находятся в проекте:

- `public/media/individual.png` — изображение по умолчанию;
- `public/media/default-calculation.mp4` — видео по умолчанию.

`resolveMedia` обрабатывает `null`, пустую строку и строку из пробелов.

`ServiceImage` подставляет локальное изображение при отсутствии URL или ошибке загрузки. `ServiceVideo` использует локальное видео, а при невозможности его воспроизведения — изображение.

У видео установлены автоматическое воспроизведение, повтор, отключённый звук и воспроизведение внутри страницы.

Для демонстрации откройте карточку с ID 12: оба адреса медиа у неё равны `null`. На плитке отображается изображение по умолчанию, в ленте — локальное видео.

Внешнее S3-хранилище для проверки не требуется.

## Компоненты и props

| Компонент | Props |
|---|---|
| `InputField` | `ageRange` — применённая возрастная группа; `onApply` — callback применения фильтра |
| `ServiceCard` | `item` — объект расчёта; `to` — адрес перехода в ленту |
| `ServiceImage` | `src`, `alt`, `className` |
| `ServiceVideo` | `src`, `poster`, `name` |

`InputField` хранит черновик значения ползунка через `useState`. После нажатия «Показать» вызывает `onApply`. Родительский компонент `ServicesPage` обновляет URL, после чего `useServices` выполняет запрос с новым фильтром.

`useEffect` синхронизирует поле с применённым значением при изменении URL. Дочерние компоненты не изменяют полученные props.

В интерфейсе используются React-Bootstrap `Card`, `Form`, `Button`, `Navbar`, `Nav.Link` и `Spinner`.

## Все используемые хуки

| Хук | Назначение |
|---|---|
| `useState` | Данные, загрузка и ошибка запроса; черновик фильтра; ошибки медиа; поля и результат регистрации |
| `useEffect` | Загрузка и отмена запросов; синхронизация фильтра; сброс ошибок медиа; изменение заголовка вкладки и прокрутка |
| `useServices<T>` | Собственный хук получения JSON и управления состояниями загрузки и ошибки |
| `useDocumentTitle` | Собственный хук изменения заголовка вкладки |
| `useSearchParams` | Чтение и изменение фильтра и параметров ленты |
| `useParams` | Получение ID карточки из адреса |
| `useNavigate` | Переходы между страницами и к следующему расчёту |
| `useLocation` | Определение активного раздела и обработка изменения адреса |

Redux, `useContext` и собственные Context-провайдеры не используются. React Router применяется для маршрутизации.

## Локальный запуск

```sh
npm ci
npm run dev
```

Плитка: `http://localhost:5173/services`.

Бэкенд запускать не требуется. Для работы MSW браузер должен разрешать Service Worker на локальном адресе.

## Проверка интерфейса

1. Открыть плитку и убедиться, что показаны mock-карточки.
2. Применить фильтр по возрасту и проверить запрос в Network.
3. Открыть карточку в ленте.
4. Проверить раскрытие описания и переход к следующему расчёту.
5. Открыть ID 12 и проверить медиа по умолчанию.
6. Проверить, что в navbar доступны только «Лента» и «Плитка».
7. Открыть `/register` и выполнить учебную регистрацию.
8. Убедиться, что ответы mock API содержат заголовок `x-data-source: mock`.
